# 千丝傀智前端体验设计

| 项目 | 内容 |
|---|---|
| 范围 | 用户平台与管理平台 Web 前端体验 |
| 关联 | `docs/product-requirements.md`、`docs/design-user-platform.md`、`docs/design-admin-platform.md` |
| 状态 | 设计基线；不规定具体前端框架或实现代码 |

## 1. 设计目标

前端包含两种面向不同任务的工作台：

- **用户平台**：帮助用户快速接入 API，清楚管理 API Key、余额、Token 用量和请求结果。
- **管理平台**：帮助运营人员管理供应商和模型、评估并发布评分、处理账户和额度、观测调用成本与异常。

用户平台以接入和自助服务为主；管理平台以高信息密度、可审计的运营操作为主。两个入口可共享颜色、字体、表格、表单和状态组件，但不共享同一套导航和权限上下文。

核心原则：

1. **Token 与费用是用量主指标。** 请求次数是辅助指标，绝不以请求数取代输入/输出 Token。
2. **状态和下一步操作优先。** 页面需要告诉用户当前状态、发生了什么以及能做什么。
3. **策略信息按角色展示。** 用户看到实际使用模型和自己的用量；内部评分、候选排名、权重和路由公式只在有权限的管理页面展示。
4. **高风险操作可理解、可确认、可追溯。** 发布评分、调整额度、撤销密钥等操作明确说明影响。
5. **桌面优先管理、响应式用户端。** 管理页面适合桌面密集操作；用户端在窄屏下保持主要查询和密钥管理可用。

## 2. 信息架构

### 2.1 用户平台

```text
用户平台
|-- 概览
|-- API Keys
|-- 兑换流量包
|-- 用量与请求
|   |-- 用量统计
|   `-- 请求记录
`-- 账户
    |-- 个人信息
    `-- 安全与登录
```

### 2.2 管理平台

```text
管理平台
|-- 概览
|-- 供应商与模型
|   |-- 供应商
|   `-- 模型目录
|-- 评估与评分
|   |-- 刷新任务
|   |-- 评分版本
|   `-- 发布/回滚
|-- 路由策略
|-- 用户与额度
|-- 流量包与兑换码
|-- 用量与成本
`-- 审计日志
```

导航项和操作按钮按 RBAC 权限裁剪；隐藏入口不是安全边界，后端仍需逐请求授权。用户端和管理端使用明确不同的应用入口，避免管理员身份与普通用户身份混淆。

## 3. 视觉方向

建议采用**清晰、克制的开发者工具风格**，不做营销型大屏：

- 中性浅色主界面，深色文字，单一靛蓝/蓝紫色作为主操作强调色；错误、警告、成功使用语义色并同时配文字/图标，不只靠颜色表达。
- 页面标题、说明、主要操作、筛选区、内容区层级一致；表格适合扫描，金额和 Token 使用等宽数字或右对齐。
- 状态统一为标签：可用/停用、成功/失败/处理中、候选/已发布/失败等，状态文案与服务端状态枚举映射明确。
- 用户端突出余额与快速开始；管理端突出健康状态、待处理事项和关键操作。
- 图表只用于趋势和比较；必须同时提供具体数值、时间范围和空数据解释。

具体颜色值、字体、品牌 Logo、图标库和组件库属于视觉定稿/实现阶段，本文不预设技术选型。

## 4. 用户端页面

### 4.1 概览

桌面布局草图：

```text
+------------------------------------------------------------------+
| 千丝傀智                         文档    账户菜单                 |
+--------------------+---------------------------------------------+
| 概览               | 概览                         [本月 v]       |
| API Keys           |                                             |
| 兑换流量包         | +-----------+ +-----------+ +-----------+   |
| 用量与请求         | | 可用额度  | | 输入Token | | 输出Token |   |
| 账户               | | ￥8.00    | | 50,000    | | 32,000    |   |
|                    | +-----------+ +-----------+ +-----------+   |
|                    | 请求数 120（辅助）   本月扣费 ￥0.24       |
|                    |                                             |
|                    | 快速开始                                    |
|                    | Endpoint [https://.../v1]       [复制]     |
|                    | [创建 API Key] [查看接入示例]               |
|                    | 默认模型 [auto v]                             |
|                    |                                             |
|                    | 最近请求                                    |
|                    | 时间 | 请求模型 | 实际模型 | 输入/输出 Token | 费用 | 状态 |
+--------------------+---------------------------------------------+
```

指标规则：

- 顶部展示可用额度、所选周期的输入 Token、输出 Token；请求数和费用作为补充指标，不替代 Token。
- 默认时间范围为本月，可切换时间范围；统计值应与服务端用量接口及其 UTC 时间边界一致。
- 近期请求表展示实际模型、输入/输出 Token、用户扣费、状态、延迟和时间。若请求模型为 `auto`，单独显示“请求模型：自动”，实际模型显示实际使用的模型。
- 空状态说明尚无调用，并引导创建 API Key 和查看接入示例；额度不足时提供兑换流量包入口。

### 4.2 API Keys

列表列：名称、Key 前缀、状态、创建时间、过期时间、最近使用、限速；操作包括禁用/启用和撤销。撤销不可逆，须二次确认并说明现有客户端将无法继续调用。

创建流程：填写名称、可选过期时间和每分钟限速 -> 创建成功 -> 单次密钥展示页。密钥只在成功响应后展示一次；提供复制按钮、明显的“请立即保存”提示和离开确认。离开后任何页面均不提供再次查看完整 Key 的入口。

### 4.3 兑换流量包

页面提供兑换码输入框、提交按钮、错误反馈和兑换成功结果。成功后明确展示本次到账额度及最新余额；重复兑换、过期、无效或已删除兑换码分别显示可理解错误，不泄露不属于当前用户的资源信息。

### 4.4 用量统计与请求记录

统计卡片的主序为：输入 Token、输出 Token、扣费；请求数为辅助。趋势图按日期展示输入/输出 Token 和费用，支持切换时间范围，并允许用户识别统计口径。

请求列表列：时间、请求模型、实际模型、状态、输入 Token、输出 Token、费用、延迟。支持按时间和模型筛选、分页；状态失败时可展开查看面向用户的失败原因，但不展示供应商密钥、候选模型评分或内部路由证据。

### 4.5 账户与安全

展示邮箱、昵称、账户状态和登录安全操作。登出、会话过期、账户停用需有明确反馈；敏感操作不在用户端暴露管理平台权限和运营信息。

## 5. 管理端页面

### 5.1 概览

```text
+------------------------------------------------------------------+
| 千丝傀智 管理后台                 环境/状态       管理员与角色   |
+--------------------+---------------------------------------------+
| 概览               | 平台概况                    [今天 v]       |
| 供应商与模型       | 活跃供应商 | 可用模型 | 已发布评分版本     |
| 评估与评分         | 请求数 | 输入Token | 输出Token | 用户扣费 | 上游成本 |
| 路由策略           |                                             |
| 用户与额度         | 待处理                                     |
| 流量包与兑换码     | 供应商连接失败   评分候选等待发布            |
| 用量与成本         |                                             |
| 审计日志           | 请求趋势 / 模型成本趋势 / 最近异常           |
+--------------------+---------------------------------------------+
```

管理端同样将输入/输出 Token、用户扣费和供应商成本作为重要指标，明确区分“用户收入/扣费”与“供应商成本”，避免把不同口径混成单一金额。首页只展示当前管理员有权查看的数据。

### 5.2 供应商与模型

供应商页支持配置、连接测试、启停和密钥脱敏展示；模型页支持发现、手动添加、能力/协议/上下文/价格/状态筛选。停用、删除等操作显示对路由和既有记录的影响。供应商密钥和用户 API Key 永不展示完整值。

### 5.3 评估与评分

刷新任务页展示固定参与模型数、成功/失败数、进度、耗时和评估成本。评分版本页明确区分当前线上版本、候选版本、失败版本和历史版本。

候选发布确认页至少列出：候选版本 ID、参与数、有效新评分数、成功率、未成功模型、历史评分回退情况、将影响的模型范围及操作者权限。达到阈值只意味着“允许发布”，不代表自动发布。发布前二次确认；发布结果显示新版本是否已在运行时生效。快照未生效时显示发布未确认和重试状态，不误报成功。回滚要求填写原因并记录审计。

### 5.4 路由策略

表单分组展示硬约束、能力/成本倾向、高风险质量优先和可用性策略。低成本倾向使用滑块并配有“质量优先 / 平衡 / 成本优先”文字解释；硬约束单独呈现，明确低成本倾向不能突破能力底线。保存前展示变更摘要，保存后记录操作者与时间。只有具备策略权限的管理员可见和编辑内部路由设置。

### 5.5 用户、额度与流量包

用户列表支持按状态、额度和用量筛选；用户详情展示账户状态、API Key 状态、额度余额、输入/输出 Token、用户扣费及最近请求。人工调整额度必须填写原因并确认调整方向/金额；成功页展示账本结果和审计记录标识。

流量包列表展示面额、状态和有效期；兑换码批次展示生成数量、已兑换数量、未使用数量和过期数量。完整兑换码只在创建/生成时按既有接口规则提供，不在普通列表中暴露。

### 5.6 用量与成本、审计

用量与成本支持按用户、Key、供应商、模型、时间范围、状态筛选；至少展示请求数、输入 Token、输出 Token、用户扣费、供应商成本、延迟和失败数。用户扣费与上游成本分列，聚合结果可下钻到请求记录。

审计列表展示操作者、动作、对象、时间、原因和结果；敏感凭证字段脱敏。无对应 RBAC 权限时不展示操作入口，直接访问仍由服务端拒绝。

## 6. 通用交互状态

所有列表、统计卡片和图表都需设计：加载、空数据、请求失败、无权限、筛选无结果、部分数据不可用状态。表单校验在提交前给出字段级提示，服务端错误保留用户已填写内容。

危险操作使用确认对话框，明确对象、不可逆性和影响；重复提交由前端禁用按钮并依赖服务端幂等保护。长时间任务（评分刷新、批量生成兑换码）显示进度和可恢复状态，离开页面后可从任务页重新查看。

数值展示规则：

- Token 使用整数分组格式并标清输入/输出，不用含义模糊的“用量”代替。
- 额度和费用按微元存储、前端格式化为人民币元；用户扣费与供应商成本使用不同标签。
- 时间显示采用用户本地时区，详情可查看完整时间；统计区间说明时区和边界。
- 所有图表提供文本数值或表格替代，键盘可操作，状态不只依赖颜色。

## 7. 首版关键验收

1. 用户概览明确同时展示输入 Token、输出 Token 和可用额度；请求数只作为辅助值。
2. 用户请求记录能区分请求模型与实际模型，并显示输入/输出 Token、费用和状态。
3. 新建 API Key 后只展示一次完整密钥；列表和后续详情不泄露密钥。
4. 管理端评分候选达到阈值后显示“可发布”，不会被界面描述成已自动上线；发布成功以运行时快照生效为准。
5. 管理端用量视图将输入 Token、输出 Token、用户扣费和供应商成本分开展示。
6. 用户看不到内部评分与路由策略；无权管理员不能执行受 RBAC 保护的操作。
7. 核心用户流程在窄屏可用；管理端桌面表格在窄屏下可横向滚动或切换为卡片，不丢失关键字段。
